# M2 脚本

## 0. 改稿规则（最先看）
你提出修改脚本的要求时：**直接给完整的新版脚本，只给最终稿**。
- 不在脚本里标注改了哪里，不附"本版变化"的清单，不逐条解释为什么这么改。
- 回复里也不写修改说明；你想看最终稿，就只给最终稿。
- 你主动问"改了什么"时才说明。

## 1. 钩子（前 5 秒）
- 第一句 **≤20 字**，含一个"利益词"或结果（省多久、做出了什么、免费、一个人）。
- **5 秒内必须出现一次成果画面**，用画面兑现承诺；不寒暄，不讲"今天我们来……"。
- 三种可选开法：
  1. **结果直给**：`你看这个报价单，客户一发需求，三分钟就出了。` → 直接切成品
  2. **今天＋动作＋结果**：`今天我让 AI 把订单对账，做成这样。` → 第 4–6 秒切成品
  3. **痛点直给**：`每次翻七八个 Excel 对发货和收款，我受够了。` → 3 秒后切到解决后的画面
- **不做身份句**（不说"白天我做外贸"之类的自我介绍），直接给结果。涉及雇主／客户信息一律脱敏。

## 2. 结构骨架（照搬木子：总-分-总＋编号章节）

```
0  钩子 + 成果展示                          0:00–0:15
1  痛点／成本算账（具体数字，传统方案 vs AI）    0:15–0:45
2  路线图：一句话交代共几步                   0:45 前
3  章节 01…0N（每章 30–90 秒）
4  完整成品展映（15–40 秒，无解说，原声）       通常放在高潮章节
5  总结：复述做了什么，用"我们一起……"
6  收尾（最后 15–30 秒，写法见 M6）
```

## 3. 章节（照搬木子）
- **章节名**：动词短语，2–4 字，直接用这一步在做的事命名。木子的例子：`拆站／设计／生成／成品`、`选机器人／装环境／强化学习／教新动作`。
- **章节数**：短视频（3–6 分钟）4–7 章，长教程（15 分钟以上）8–9 章。
- **每章循环**：痛点 → 实操 → 结果 → 一句点评。
- **难度阶梯**：入门（3 步）→ 垂直商业场景 → 专业精控。
- 讲原理时用 6–8 个设问串起来，配生活类比，不堆术语。
- **点评**：木子每期至少一次"美中不足／和标杆相比还有差距"，放在章节点评里，一句话。你的点评可以是一句局限，或一个小心得，没有就不硬凑。

## 4. 数字算账
- 每一步配"之前 vs 现在"的**真实**耗时／金额／数量。
- 没有记录就不写数字，只写占位符让你补，不编。

## 5. 限制怎么说
- 一句话带过，放在章节点评里；不编出错情节。
- 不要成串罗列使用条件、前置要求、各种异常情况；详细的放简介或置顶评论。

## 6. 口播
- 人称：以"我"（真实经验）为主，"我们"（带着做）和"你"（指引）穿插；不喊口号、不制造焦虑。
- 大白话类比：`术语听着玄，其实就是……`。
- 避免：`震惊／炸裂／99%的人不知道`、感叹号堆叠、"首先／其次／综上"、一键三连。
- **语速**：按 **240–280 字／分钟**写稿；录完剪气口、按段加速（做法见 [M5](M5-声音.md)）。木子的 300–330 字／分钟且气口全剪，节奏过密，你此前明确不要"赶"，不采用。

## 7. 句式（结构参考，不原句照搬）
| 用途 | 句式 |
|---|---|
| 成果前置 | 今天我让 AI【动作】，做出这样的【成果】。 |
| 去门槛 | 整个过程不需要我自己【A】【B】，都是 AI 干的。 |
| 成本反差（须有实测） | 这个以前我要【真实耗时】，现在【真实耗时】。 |
| 一句话指令 | 我就一句话告诉它【任务】，它自己【动作一】【动作二】。 |
| 极限兜底 | 我这台【普通设备】能跑，你的电脑大概率也行。 |
| 打破误区 | 你可能以为【直觉做法】，但实际上【真相】。 |

## 8. 结尾
- 结尾三拍：**复盘一句 → 价值句（本期自己的结论，不是口号）→ 一个有理由的动作**，说完即停，不加片尾卡和告别语。各版本能用哪些动作，见 [M6 结尾](M6-平台版本与合规.md)。
- **不求三连、不做情绪升华**（"日子越过越有盼头"是木子的味道，你用会显得套路）。
