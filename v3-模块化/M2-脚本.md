# M2 脚本

## 0. 写稿流程（最先看）

### 0.1 先采访，再写稿
在制作视频脚本之前，先查看你给的项目链接，看下这是个什么项目，然后担任采访者来采访你。采访的目的，是通过提问对这个项目有更深入的了解，以及了解你对这个项目主要要呈现的内容和东西的理解，从而减少写脚本时的 AI 味：

1. **动态追问**：每次只问你 1个问题，不要一次列一堆问题；根据你上一轮的实际回答，追问原因、具体做法和细节。尽可能的深的挖出我的深入的想法，因此从不同的角度多问几轮，直到你认为已经获得了足够多的信息，不怕问的过多或者我回答的重复，因为你可以后期删减。
2. **保留原话**：你会用语音输入回答，里面可能有同音错别字或口语停顿，直接理解原意，并把每一轮回答的原始输入一字不改保存下来。
3. **先确认底稿**：聊清楚后先别直接写脚本，按文章脉络归拢一份 100% 来自你原话的底稿，发给你确认。
4. **只整理不脑补**：确认后正式成文时，严格以你的原话为唯一版本，只做适合于这个视频脚本的结构梳理和语句润色，绝不擅自脑补你没说过的观点，允许为了视频的精彩和整体节奏进行删减，但是尽量不要增加。

### 0.2 改稿规则
你提出修改脚本时，直接给完整的新版脚本，只给最终稿：不标注改动、不附变化清单、回复里也不写修改说明；你主动问"改了什么"才说明。

## 1. 钩子（前 5 秒）
- 第一句 ≤20 字，含结果或利益词；5 秒内出现成果画面；不寒暄，不说身份句（不说"白天我做外贸"之类）。
- 开法：结果直给／今天＋动作＋结果／痛点直给（3 秒后切到解决后的画面）。

## 2. 结构（照搬木子：总-分-总＋编号章节）

```
0  钩子 + 成果展示                          0:00–0:15
1  痛点／成本算账（具体数字，传统方案 vs AI）    0:15–0:45
2  路线图：一句话交代共几步                   0:45 前
3  章节 01…0N（每章 30–90 秒）
4  完整成品展映（15–40 秒，无解说，原声）       通常放在高潮章节
5  总结：复述做了什么，用"我们一起……"
6  收尾（最后 15–30 秒，写法见 M6）
```

## 3. 章节
- 章节名：动词短语，2–4 字，用这一步在做的事命名（拆站／设计／生成／成品）。短视频（3–6 分钟）4–7 章，长教程（15 分钟以上）8–9 章。
- 每章：痛点 → 实操 → 结果 → 一句点评。讲原理用设问串联，配生活类比，不堆术语。
- 点评放一句局限或小心得，没有就不硬凑，不编出错情节。限制一句话带过，或者干脆就不说了，我就不明白在视频里有啥好说的。不成串罗列使用条件、前置要求、各种异常情况；详细的放简介或置顶评论。

## 4. 数字
每一步配"之前 vs 现在"的真实耗时／金额／数量；没有记录就不写数字，只写占位符让你补，不编。

## 5. 口播
- 以"我"为主，"我们""你"穿插；不喊口号、不制造焦虑。
- 避免：震惊／炸裂／99%的人不知道、感叹号堆叠、"首先／其次／综上"。
- **开头不许卡壳**：钩子里若有磕绊、重复起句，只留最后一遍完整的，其余全剪掉（逐字对齐对不准时，直接按时间切原声，字幕单独写）；开头一卡壳观众就走了。
- **同一个词别在一章里反复出现**：例如"解决／直接解决"重复三四遍就啰嗦，剪辑时合并、删减，一章只留一次强调。
- 语速：按 240–280 字／分钟写稿；录完剪气口、按段加速（见 [M5](M5-声音.md)）。
